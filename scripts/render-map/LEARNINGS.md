# render-map — LEARNINGS

Dated, one line per lesson: what we believed → what the data said. What it cost to learn is the
reason it is here; the rules themselves live in README / the render-map skill (`.agents/skills/render-map`).

## 2026-10-29 — Emerald Sanctum 1.12 terrain

- **Monolithic does not mean nested-chunk scanning works.** Emerald's `MCNK` data after `MCNR` is not reliable to iterate as generic chunks. The 1.12 header offsets at 0x14/0x1c/0x24 point directly to the `MCVT`/`MCLY`/`MCAL` payloads; validate those ranges and normalize them in memory for the existing terrain pipeline.
- **Legacy splat alpha is packed.** Observed Emerald layers use 2048-byte 4-bit `MCAL`, two pixels per byte. Named `MTEX` BLPs must resolve through the MPQ chain, and provenance must retain each winning archive.
- **Omission must be explicit.** M2 placements are counted and documented but not meshed. A monolithic terrain ADT with `MODF` aborts, because silently dropping placed WMO geometry would produce a plausible but incomplete map.

## 2026-10-18 — Blackwing Lair (placed WMO, `placed_wmo:`)

- **"BWL is a terrain map, so it needs the 1.12 terrain reader."** Belief from the inventory row (16 ADT tiles). Result: the tiles are outdoor dressing; the raid is one WMO placed in ADT 33_45 at yaw 35°, the same placement in stock and OctoWoW. Reading the ADTs' MODF and placing the WMO (adt2obj's verified convention, extent error 0.001 yd) is enough; the terrain reader stays unbuilt.
- **"Stock" = the first archive was wrong here.** BWL's stock root and groups 018–023 come from Blizzard's 1.12 patch.MPQ (wmo.MPQ holds an older root). mpq_wmo_diff now takes the last archive before patch-3.
- **Liquid can disappear.** OctoWoW's copy of the 96-tile lava group has no MLIQ chunk; the 1.12 model renders without lava, no tint in the entry.
- **No log to check.** octo has no BWL logs at all (799 public); capy 76, none with `unit-position`. Registration checked by overlay on chronicle's native turtle map (its UiMapAssignment region), which already labels OctoWoW's new "Alchemical Laboratory".

## 2026-10-18 — Molten Core for OctoWoW/Cappy (octo log 7-iLUZni-SXeQnNE)

- **"No new content."** Belief (relayed): OctoWoW/Cappy are forks without new content. Result: patch-8.mpq adds three MC wings (LizzardCave, Ruinedcity ×4, guildmount.001: +44 % area, +8,561 lava tiles) holding Turtle's Incindis, Basalthar & Smoldaris and Thaurissan. CDN = stock 1.12 here (99.89 % of triangles): Onyxia's retriangulation was not universal.
- **The 2 % camera margin.** blender_topdown frames at 1.02 × span, so every pass (and height.png) covers 1 % more per side than `bounds_wow`/`frame_world`. check_log_positions ignored it: with it, ZG's |logged z − top| ≤ 3 yd went 86 % → 92.7 % and "under something" 6.2 % → 3.1 %. ZG's published render (plain downscale) is 2 % small in chronicle → `chronicle_render.py`.
- **WMO passes are south-up.** A WMO pass with rot −90 is the pipeline frame (world turned 180°); chronicle's render layer is north up. Placement check: 100.0 % turned, 58.2 % not. Same for height.png: only negated log x/y land on geometry (100 % vs 0 % for the three other axis choices).
- **Lava streams are floor.** The first export's top surface over Ragnaros was −92 over a −230 floor: `lavafloortrans` streams slope upward, form ≥ 10 sq yd patches, so they were FLOOR seeds and survived with their walls culled. The no-z fallback would have stood the raid on them. `--seed-exclude lavafloortrans`: 699 faces, Ragnaros hot spot gone; the lava rim around the spiral stays (within 8 yd of floor).
- **Top ≫ floor is not always a roof.** The remaining > 20 yd samples (4.3 %) are the Ruined City ring walkway over a 40-yd lava pit: the walkway is where units are, so highest hit is right. Plot the hot samples before tuning.

## 2026-10-18 — Zul'Gurub in chronicle (octo log OJbOLvyr1pXA3AX9)

- **height.png is not linear.** Belief (height.json `encoding`): grey = (z − z_min)/(z_max − z_min). Result: logged z sat a median 88 yd BELOW the decoded surface on every sample; after sRGB→linear the median is 0.0 yd and 86% are within 3 yd → Blender's view transform is baked into the PNG. Same check pinned the orientation (`rot: -90`: north up, east right; the six other mappings scatter) and showed the octo log's z is in the mesh's frame, no offset. Fixed the same day: export_glb renders height.png with the Raw view transform, `encoding` now starts with "linear" (the checker auto-detects). The linear ZG re-export (GLB byte-identical to the sRGB one): median +0.0 yd, 92.7% within 3 yd — better than linearising the old sRGB file (86%), whose curve had squeezed the low end.
- **Pillow and 16-bit RGBA.** `Image.open` gives mode RGBA, 8 bit: it keeps the high byte only (exactly; the low byte is non-zero on 96% of ZG pixels), ~1.2 yd steps over ZG's 315-yd range. No 16-bit reader in the venv → `check_log_positions.read_png16` (zlib + numpy unfilter, ~25 s for 2400², verified MSB == Pillow).
- **No z, then z.** The API stream had no z at 2026-10-17 (parsed v1.0.73, before chronicle #1156); after a reparse every sample carries it. Check the stream, not the format name.
- **Highest hit on terrain.** On the linear ZG export: 6.1% of samples have the top surface > 8 yd above the floor within 4 yd, and 3.1% stand > 5 yd under the top surface (huts, canopies, bridges). That is the share the no-z fallback puts on a roof.
- **The toggle needs bounds.** The mesh alone did not show "3D map" on ZG: the native floor has no world bounds, so chronicle resolved the zone map (619). A calibrated 2D render with the mesh's bounds fixed it.
- **Octo API.** `/api/v1/raidlogs/...` answers 403 to curl; browser headers (Origin, Referer, Sec-Fetch-*) pass. `events/unit_position` = gzip of (encounter id, first ts, count, length) headers + varint-delimited `UnitPosition` protos (field 7 = optional z).

## 2026-10-14 — terrain GLB (Ruins of Lordaeron)

- **Slab under the cut edge.** Hypothesis: the blue slabs under the north edge of the 3/4 proof were the MH2O sheet lying flat under the land, kept because a probe ray from a vertex ON the frame edge grazes the terrain's border edge and misses → clamped probes 1 cm inside the frame: no change (the clamp is correct and stays, but it was not the cause). Hiding the liquids left the slab in place: it was solid Undercity wall at world z ≈ −24, kept because one tall face ran from underground up past the surface, under a terrain hole → straddle rule (a face whose centroid is > 10 yd below ground goes). Most of `liquid_31_29` sits at z 32.9, ABOVE the ground: it is the real lake and is right to stay. Lesson: hide liquids before blaming water; a slab under a cut edge means something underground survived.
- **Double-placed city WMO.** Belief: one MODF entry per WMO. Result: a WMO spanning tiles is listed in every overlapping tile's obj0 with the same uniqueId; city WMO 114612 (uid 65749827, in 31_28 and 31_29) was meshed twice: 510k coincident triangles, invisible in every pass, doubling the GLB → adt2obj places each MODF/MDDF uid once (1,107,222 → 588,778 triangles).
- **180° turn.** Belief: the terrain OBJ shares the WMO OBJ's frame. Result: adt2obj writes TRUE world coordinates (log `bounds lo=(1233, -133, …)`), while wmo2obj's frame negates both horizontals (chronicle's manifest negates `bounds_wow` to get world) → turn the terrain model 180° about z before export (a rotation, so winding survives), and render `height.png` unturned with the passes' camera. Checked: POSITION extent == `bounds_wow`, deviation 0.0.
- **Buried cull.** First rule, "terrain straight above the vertex", dropped 298k faces but kept the Undercity under the palace (z down to −70, 22.5 MB): the palace replaces the ground, so the terrain has a HOLE there and "terrain above" never fires → fill the heightfield across holes on the 4.17-yd vertex grid (−376k faces, 15.6 MB). That also took the floors out from under the sunken palace pools (water floating over a void) → in a hole, buried also requires solid geometry covering the vertex from above; water does not count, so the pool floors came back.
- **Roofs.** Belief: a roof cull limited to interior (MOGP 0x2000) groups opens the throne room. Result: the dome and tower caps are EXTERIOR shells over interior floors; interior-only removed 7.2k faces and opened nothing visible. Any group over an interior floor 2..25 yd below opens tower/gatehouse ceilings, not the dome (~100 yd up); a 150 yd reach opens the dome, raggedly → roofs kept by default, `--roof-cull` is opt-in. Only 114612 has interiors at all; the 7 ruins and 3 props have none. Chronicle's floor probe takes the highest hit, so units inside stand on the roof.
- **Atlas 6 px/yd.** The 512 px/chunk bake is 8192 px per tile, which would dominate a web GLB → downscale to 6 px/yd and crop to the UVs in use: two 3002 px atlases plus two 202 px strips, 1.37 MB of WebP; all images 3.97 MB of the 15.6 MB. Geometry (11.6 MB) is the size driver, not textures; the size came from the culls.
- **16-bit check.** PIL opens a 16-bit RGBA PNG as 8-bit, so it "looked" 8-bit → read the IHDR bit depth (byte 24 = 16) or decode raw (both the Wailing Caverns and the Lordaeron height maps are 16-bit RGBA).
- **Regression proof is cheap.** Re-running `render_set.py wailing-caverns … --glb` with the previous GLB version's args after the change gave a byte-identical GLB and pixel-identical `height.png`: gate WMO-path changes on that.

## 2026-10-16 — 1.12 MPQ clients (OctoWoW Onyxia, `source: mpq`)

- **"No listfile, names unknown."** Belief: OctoWoW's patches had no (listfile), because `strings` showed no `world\` paths. Result: every archive (base, patch, patch-2..A, locale patch-L) carries a `(listfile)`. It is compressed, which is why `strings` saw nothing. StormLib resolved every entry (0 unnamed), so no community listfile was needed.
- **Wrong WMO.** Belief: Onyxia = `kl_onyxiaslair.wmo`. Result: map 249's WDT places `kl_onyxiaslair_b.wmo`; the unsuffixed and `_a` sets in the same directory are unused. Read the WDT's MWMO (or the CDN root fid's listfile name); never pick by directory.
- **"Different" that was the same.** CDN Classic Onyxia vs stock 1.12: only 70 % of triangles match, but the bbox is identical, area agrees to 0.02 %, lava tiles agree, and 97.6 % of vertices are shared. The Classic re-export retriangulated (−32 % triangles). So compare vertex sets and area: the triangle overlap alone would have called stock = CDN a geometry change.
- **Stock vs custom archives.** Block flags do not separate them: base wmo.MPQ uses `80000200` just like the custom patches. Stock = everything before patch-3, because patch-2.MPQ (Blizzard 1.12.1) carries the 44-row stock Map.dbc and the custom Map.dbc in patch-9 has 57 rows.
- **The fork used the modern Onyxia.** OctoWoW's patch-9 groups 000/003/005/006/007 equal the CDN groups vertex for vertex (100 %); stock matches only 57–100 %. So the custom WMO started from a post-vanilla export, not from their own client's stock file. Diff a fork against CDN AND stock.
- **WMO GLB bounds.** README wording ("POSITION extent equals bounds_wow") is exact for terrain only. For WMO maps `bounds_wow` is the full model before the support cull, so the open-top extent can sit inside it: Wailing Caverns by up to 10.3 yd, Onyxia-octo by 3.4 yd (a culled ceiling at the east room). Not a regression.
- **StormLib on homebrew** fails cmake on `libtommath` → `-DSTORM_USE_BUNDLED_LIBRARIES=ON` (mpq_chain.py does this).
