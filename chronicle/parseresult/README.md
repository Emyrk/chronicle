# Data-only parse result (experimental)

`ParseWithFailures` turns a combat-log reader and read-only game-data interface into a JSON-serializable `ParseOutcome` (successful `Result` values plus labeled per-instance failures). `Parse` retains all-or-error behavior for existing callers. The caller must provide the resolved dataset, flavor and talent-tree parse context when those values matter; the parser cannot infer them from raw log bytes. The currently supported formats are 1.12a, 2.4.3 and 3.3.5 CC-addon logs. The 3.3.5 path does not yet inject sidekick storage artifacts.

This is **not** the production parse pipeline. `WorkerLogParse` remains unchanged. The result is a parser-derived projection, not a complete persistence contract: realm/tenant resolution, source identity, parse generation, write-time rankability, visibility, slugs, game-data item metadata, generated IDs and downstream effects belong on the primary. No remote artifact transport, ingest job or primary orchestration is connected yet. Do not treat the individual `InsertParsed*` functions as a replacement for the worker without a transaction/generation fence, complete side-effect handling and whole-database parity.

Does not compare jobs, reports, ranking-run effects or SpiceDB relationships. |
| Vanilla real worker versus transported trash ranking rows | `TestLegacyAndDataOnlyParsePersistSameTrashRankings` | Clean non-boss fight only; no complete ranking-run side effects or replacement generation. |
| 2.4.3/3.3.5 worker versus transported core, overview, encounter and event rows | `TestLegacyWorkerCLEUProjectionMatchesDataOnlyParse` | Separate DBs, initial and replacement generations; minimal CLEU swings, without populated player/guild/loot/rankings or sidekick input. |

The adapters for core, events, loot, armory, speedrun and rankings are separate bounded functions in `chronicle/parse_result_*.go`. The initial schema (v1) records the resolved parse flavor, dataset ID, and exact daemon parser build (`GitTag+GitCommit`, distinct from the schema version). `ValidateParsedResultProvenance` requires the recorded parser version and compares format, flavor and dataset to independently resolved primary values; it does not require a build match. Future remote ingestion must call it before writes, rather than using payload identity as authority. Before deployment, the job must carry the creator's exact build in durable arguments and invoke `ValidateParsedJobVersion` at the start of each attempt, before side effects: a headless executor requires an exact match, while full `chronicled` does not. Executor mode must come from trusted local configuration, never the job payload. No upload or ingest job is wired yet; the existing resync CLI's release-tag-only check is unrelated to this policy. Core and speedrun accept all three supported formats; boss and trash ranking ingestion remains 1.12a-only until CLEU ranking rules and persistence are compared. Tests normalize generated row IDs, slugs, trigger timestamps and encounter UUID stream headers; they compare substantive timestamps and metrics. Each mismatch is labeled with a `cmp.Diff` of legacy versus transported rows.

A complete rollout still needs the approved ZIP-over-HTTP artifact handoff implemented, authenticated/validated primary ingestion with stale-generation and same-generation retry safety, all worker write-time and downstream side effects, representative nonempty format-specific fixtures, and whole-database parity. Production must not switch on the basis of this bounded test matrix.
