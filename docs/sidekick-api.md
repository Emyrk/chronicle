# Chronicle Sidekick integration

Chronicle identifies each Sidekick installation separately so an account can monitor and disconnect multiple computers.

## Stable installation identity

Sidekick must generate a UUID once and persist it for the lifetime of that installation. Reuse the UUID when reconnecting the same installation. Do not derive it from hardware identifiers.

Include these fields in the OAuth device authorization request to `POST /oauth/device/authorize`:

| Form field | Required | Description |
| --- | --- | --- |
| `client_id` | yes | `chronicle-sidekick` |
| `scope` | yes | `all` |
| `installation_id` | yes for managed Sidekicks | Persisted installation UUID |
| `installation_name` | no | Initial user-facing name, such as the computer name |
| `installation_platform` | no | Short platform description |
| `installation_version` | no | Sidekick application version |

Older clients without `installation_id` can still authorize and upload, but they do not appear in Sidekick settings and cannot report health.

Reauthorizing the same installation UUID revokes its previous OAuth grants. Disconnecting it from Chronicle also revokes all OAuth access and refresh tokens associated with that installation.

## Heartbeat and issues

Send `PUT /api/v1/sidekick/status` with the OAuth bearer token once per minute:

```json
{
  "platform": "windows/amd64",
  "sidekick_version": "0.7.0",
  "config_hash": "03ba74a583c3e096527eb448a456583b975a0f8c32d8517c630ff3954e3528e4",
  "start_at_login": true,
  "auto_upload_capabilities": {
    "wotlk_3.3.5a": ["on_game_exit"]
  },
  "wow_directories": [
    {
      "id": "wowdir_0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "path": "C:\\Games\\Warmane",
      "tenant_name": "Warmane",
      "tenant_base_url": "https://warmane.chronicleclassic.com",
      "realmlist": "logon.warmane.com",
      "game_format": "wotlk_3.3.5a"
    }
  ],
  "issues": []
}
```

Chronicle considers an installation running when its most recent heartbeat is less than three minutes old.

`sidekick_version`, `start_at_login`, `auto_upload_capabilities`, `wow_directories`, and `issues` are required on every heartbeat. Empty capability, directory, and issue collections are valid.

`sidekick_version` is the installed Sidekick application version. The old top-level `version` field is not part of the heartbeat contract.

`start_at_login` is observed local state. Chronicle displays it but does not manage it through the returned configuration.

`auto_upload_capabilities` lists the format and trigger combinations implemented by that Sidekick version. `disabled` is always supported implicitly and must not be listed.

`wow_directories` is the complete snapshot of detected WoW installs. Each entry uses the exact opaque `id` generated by Sidekick. Chronicle must not calculate directory IDs. `game_format` is omitted until Sidekick has accepted a managed format assignment. Tenant and realmlist metadata may also be omitted when unavailable. Omitting a previously reported ID removes it from Chronicle. At most 50 directories may be reported.

`issues` is the complete snapshot of currently active issues:

- Use a stable, machine-readable `code` for each issue type.
- Repeating a code updates its message, details, and last-reported timestamp.
- Omitting a previously active code marks that issue resolved.
- Send an empty array when the installation is healthy.
- Messages and details must be sanitized and must not contain credentials, OAuth tokens, or private log contents.

Limits:

- 20 active issues per heartbeat
- code: 100 characters
- message: 500 characters
- details: 4,000 characters

## Managed configuration

Chronicle stores one complete managed configuration per Sidekick installation. Configuration version 1 is keyed by the exact directory IDs reported in the heartbeat:

```json
{
  "version": 1,
  "archive": {
    "enabled": true,
    "retention_days": 7
  },
  "wow_directories": {
    "wowdir_0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef": {
      "game_format": "wotlk_3.3.5a",
      "auto_upload": "on_game_exit"
    }
  }
}
```

`archive.enabled` controls whether successfully uploaded managed snapshots remain on the Sidekick computer. `archive.retention_days` is always required and must be between 1 and 365, even when retention is disabled. The default is enabled for seven days. Sidekick never deletes pending or failed uploads.

Supported game formats:

- `wotlk_3.3.5a`

Supported auto-upload modes:

- `disabled`
- `on_game_exit`, only when listed in `auto_upload_capabilities` for the selected format

If a directory ID is present, both `game_format` and `auto_upload` are required. To leave a directory unconfigured, omit its ID. Manual uploads remain available for unconfigured directories and for directories whose automatic upload mode is `disabled`.

The account settings API exposes complete per-installation configuration documents:

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/v1/me/sidekicks/{sidekickID}/config` | Read the desired configuration and canonical hash. |
| `PUT` | `/api/v1/me/sidekicks/{sidekickID}/config` | Replace the complete desired configuration. |
| `DELETE` | `/api/v1/me/sidekicks/{sidekickID}/config` | Reset archive policy and directories to their defaults. |

All installation endpoints enforce account ownership. `GET /api/v1/me/sidekicks` includes each installation's desired configuration, observed directory formats, local start-at-login state, and auto-upload capabilities.

### Canonical JSON and hashing

Chronicle hashes only the managed configuration object:

1. Serialize JSON without insignificant whitespace.
2. Preserve struct field order: `version`, `archive`, then `wow_directories`.
3. Within `archive`, preserve `enabled`, then `retention_days`.
4. Within each directory, preserve `game_format`, then `auto_upload`.
5. Sort `wow_directories` keys lexicographically.
6. Calculate SHA-256 over the UTF-8 JSON bytes.
7. Encode the digest as lowercase hexadecimal.

The empty configuration serializes as:

```json
{"version":1,"archive":{"enabled":true,"retention_days":7},"wow_directories":{}}
```

Its hash is `03ba74a583c3e096527eb448a456583b975a0f8c32d8517c630ff3954e3528e4`.

### Heartbeat reconciliation

When the heartbeat hash differs from the desired hash, Chronicle returns the complete configuration:

```json
{
  "settings_url": "/account/sidekick/installations/<installation_id>",
  "config_hash": "<lowercase-sha256>",
  "config": {
    "version": 1,
    "archive": {
      "enabled": true,
      "retention_days": 7
    },
    "wow_directories": {}
  }
}
```

Chronicle returns `200 OK` with `settings_url` and `config_hash` on every successful heartbeat. When the hashes match, it omits `config`. The relative settings URL is same-origin and opens the reporting installation directly. Chronicle never returns an automatic upload mode that the reporting Sidekick did not list for the configured format. If a previously saved mode is no longer supported, Chronicle reconciles it to `disabled`.

Sidekick validates the complete document and hash before replacing its previous valid configuration.

## Upload tracking

Continue uploading with the linked OAuth bearer token through the existing raid-log upload endpoint. Chronicle associates successful uploads with the installation embedded in the OAuth authorization and updates its `last_upload_at` timestamp.

For WotLK uploads, Sidekick passes `format=wotlk_3.3.5a` on the upload request.
