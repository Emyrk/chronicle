# Modules

Modules are account-owned Lua source packages. They remain `lua_projects` in internal APIs and storage. A project has one **main** (the latest saved source, stored as `draft_hash`) and author-tagged **releases** in `lua_project_releases`. Builds are identified by the SHA-256 of their deterministic ZIP bytes. Saving or uploading replaces main; **Tag release** inserts a release with main's hash under a unique tag (`^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$`, not `main`), guarded by the project revision. Only the newest three releases keep their hash; older ones keep their row with `hash` NULL, and artifacts no longer referenced by main or any release are queued for deletion. Panels follow the newest release with files (`lua:<id>:release`) or main (`lua:<id>:main`); saved `stable`/`unstable` refs and `?channel=stable|unstable` still work as aliases. Anyone with `use` may run main; `release` (owner, or contributors granted it) tags and deletes releases.

## Authoring and sharing

Uploaded ZIPs live in the `lua-projects` object-storage namespace (an S3 prefix when the deployment uses the configured S3 bucket; local object storage in development). The underlying S3 bucket must remain private: the S3 adapter does not set a bucket policy, and authenticated/public channel downloads are mediated by Chronicle's API. PostgreSQL holds project/channel metadata, content hashes, object keys, MIME type (`application/zip`), optional outer content encoding (NULL for the current ZIP), and the unpacked file-byte and stored-archive-byte counts. It does not store ZIP bytes. The ZIP currently uses uncompressed entries, so its stored size includes ZIP headers rather than representing a gzip-compressed length. Before each upload, PostgreSQL records a durable object-key intent. An upload that crashes before the artifact transaction or loses a revision race remains recoverable. Successful artifact transactions consume the intent atomically; upload and commit errors leave the intent untouched because acknowledgments can be ambiguous. Collectors only claim unreferenced keys after the upload's ten-minute grace period and retry failed deletions on a lease, using PostgreSQL time for eligibility and lease expiry. Cleanup runs at startup, after writes, and once a minute, so idle services still collect expired intents. The `chronicle_lua_projects_artifact_gc_backlog` Prometheus gauge counts eligible, unreferenced ZIPs waiting for deletion (including leased retries); watch for sustained growth. It is sampled on cleanup passes, so may lag by up to a minute. Earlier bytea-only artifacts must be migrated before applying the object-only migration; the migration refuses to discard them.

Authoring is opt-in via the site-wide SpiceDB relation `chronicle:chronicle#lua_project_author@user:<id>` (presented as **Module Author** in Admin Users). This grants `create_lua_project`; technical administrators receive it automatically, while ordinary site administrators need the explicit grant. Creation records `lua_project:<id>#chronicle@chronicle:chronicle`, `lua_project:<id>#owner@user:<id>`, and `lua_project:<id>#public_viewer@user:*`. Owners and technical administrators can `update` drafts and publish channels. Published metadata and packages require `view` and remain public by default, including for anonymous visitors; technical administrators retain `view` even if the wildcard is removed. Private draft downloads require project `update` permission; the public view grant does not expose drafts. Removing an author's site-wide grant prevents new projects but does not revoke update access to projects already owned; remove the project owner relation separately to revoke that access.

Module addresses are `/modules/<author>/<slug>`: the owner's unique module author name (claimed once on the Modules page; new names are 5-32 lowercase letters, digits and hyphens, and some names are reserved) and the project slug, which is unique per owner. `/modules` lists released modules and links to **My modules** at `/modules/<author>`, which lists that author's modules (`GET /api/v1/modules/<author>`, filtered by `view`). Stars (`lua_project_stars`) are how people track modules: the instance panel picker offers the tracked panel modules (`GET /api/v1/me/lua-projects/starred`, filtered by `use`), anyone who may use a module can star it (`PUT`/`DELETE /api/v1/me/lua-projects/<id>/star`), and owners always track their own (created with a star, and unstarring is refused). Untracked modules in saved layouts and shared links still run. Every project response carries `stars` and the caller's `starred`. `/modules` lists released modules most-tracked first. Each module has a `description` of up to 300 characters, kept on `lua_projects` rather than in the manifest so lists can show it without opening packages; anyone with `release` sets it from the module page (`PATCH /api/v1/me/lua-projects/<id>`). `/modules/id/<id>` addresses a module by ID and redirects to the named address; legacy ID links that arrive as `/modules/<id>` redirect there. Permissions live in SpiceDB on `lua_project`: `view` (the page and source) and `use` (running it in a panel) are granted to `user:*` on new modules, so removing those wildcards makes one private; `edit` (Workshop and drafts), `publish_unstable` and `publish` (promote to stable) come from the owner (`manage`) or from per-contributor grants the owner picks. `lua_project_contributors` lists contributors and mirrors those grants; write queries no longer filter by owner, so handlers must check the matching permission first. The module page shows visitors only published builds; people who can edit also see the draft, release actions, contributors and each contributor's AI cost.

Lua projects are presented to users as **Modules** (instance panels and guides are module kinds); the separate trusted JavaScript plugins are presented as **Developer Panels**. Create a panel at `/modules` (old `/addons` and `/lua-projects` links redirect), then open `/modules/<author>/<slug>/edit` (or `/modules/id/<id>/edit`) to edit `main.lua`, `project.json` and an optional `README.md` in the browser. This first editor accepts asset-free panel drafts with only those files; projects with additional files must be edited externally, never silently truncated. Source remains local until you explicitly save the private draft using the project's revision guard. The page header always shows whether the working copy is unsaved, saved, or published, with Save draft (Ctrl/⌘+S) and Publish unstable ("Save & publish" when there are unsaved edits), so both work from the chat, code, and preview views; promotion to stable is on the module's overview page (`/modules/<author>/<slug>`), which shows each build's files, its README.md and the releases, like a repository page. The page is agent-first: one header row holds the agent pill, which connects a local coding agent through chronicle-mcp (see below) and opens a popover with its status, last tool call, connection name, Revoke and Disconnect. The instance picker sits atop the encounter sidebar. The instance preview owns the canvas, with Code as an optional view of the same canvas; both stay mounted so the editor keeps its undo history. The preview reuses the instance page's collapsible encounter sidebar, and its size presets (12×4, 6×5, 4×4 grid panels) or drag handles hold the panel at a fixed size to check layouts. Browser chat is a secondary drawer: a durable per-project `module-workshop-panel` conversation (the panel module workshop assistant; users can turn it off in Account → AI assistant) (inference thread context `lua_project`, requiring project `update` permission on every use). Unsaved changes show an amber chip naming the changed files, an accented Save button and a `●` tab-title prefix. Storybook `Pages/LuaProjects/ModuleWorkshop` renders this route over MSW, including a scripted fake chronicle-mcp daemon. The assistant has no server-side access to drafts. It acts through the page's `lua-editor` v1 browser capability: `read_lua_files`, `edit_lua_file` (exact-match replacements or a whole-file rewrite, guarded by the working-copy revision; the file is `project.json`, `README.md` or any relative `.lua` path, so the tool already fits multi-file and directory packages, while the browser currently has only `main.lua`) and `run_startup_check`. Edits apply immediately to the unsaved working copy and show a diff with Undo (editor undo also works); the assistant cannot save or publish. Tool arguments are capped at 16 KiB, so large rewrites should use incremental edits. Damage panels replay their events once and then get a completion callback: aggregate in `damage.onEvent` (or `Panel:OnEvent("damage", fn)`) and draw in `damage.onComplete` (or `Panel:OnComplete(fn)`), because every UI change is sent to the page (more than 2,000 pending UI operations in one startup, callback or 100-event batch stops the panel). Events carry `source`, `target`, `amount`, `offsetMs`, `encounterId` and `selected`. The optional `project.json` field `stream_scope` is `"selection"` (default: only the user's selected encounters) or `"instance"` (every encounter, each tagged with `selected`); Chronicle does not cap how many events or bytes a panel receives; a panel can bound its own replay with the optional positive integer `max_events`, and the host stops a worker only after 10 seconds without progress. Panel filters are not applied to Lua panels yet. The complete author-facing API reference and FAQ is `frontend/chronicle/src/pages/LuaProjects/lua-panel-api.md`, also served in the app at `/modules/api`. Run a browser-only worker startup test, then choose a UUID-addressable instance and any encounters to run unsaved code against its damage events in the browser worker. The events endpoint serves the entire instance stream, which the preview downloads in full before selecting encounter frames locally. The tar upload remains available on the overview page. External tools can still upload the same uncompressed `.tar` format. Review and test the Unstable release in a real instance layout before promoting it to Stable.

A minimal manifest is:

```json
{"manifest_version":1,"kind":"panel","name":"Example","slug":"example","entrypoint":"main.lua","capabilities":["ui"],"streams":[],"assets":[]}
```

The manifest name, slug, and kind must match the project record. Supported capabilities are `ui` and `input`; the only available event stream in this release is `damage`. The panel resolves the channel's current SHA-256 from `/api/v1/lua-projects/<id>?channel=<stable|unstable>` (uncached metadata), then downloads `/api/v1/lua-projects/<id>/artifacts/<sha256>/package`. Only currently published hashes can be fetched. Public responses have a one-hour shared-cache TTL and an ETag; a removed or revoked publication may remain in an HTTP cache until that TTL expires. Private draft preview uses `/api/v1/me/lua-projects/<id>/draft/<sha256>/package` with `no-store`. An Unstable reference is `lua:<project UUID>:unstable`, and Stable uses `:stable`. Only the signed-in owner's published Stable and Unstable panels appear in instance selectors; other users do not discover panels there until tracking/favorites are implemented. Published releases remain link-accessible through their API URLs. A saved layout stores the channel reference, **not** a specific digest. The panel resolves the channel once per browser page load and keeps that hash while the page remains open, including across panel remounts. Refresh the page to pick up a new release.

Use `require("chronicle.v1.ui")` for shared metric, table, and bar helpers and `require("chronicle.v1.events.damage")` for `onEvent`/`bySource`. These modules ship with Chronicle, not in each project ZIP. The `chronicle` namespace is reserved; package-local Lua modules can be required from other names. Host-owned processing passes bounded event records to the worker. There is no Lua network, DOM, JS interop, or generic HTTP function.

For a simple damage panel, declare `"streams":["damage"]` and write:

```lua
local ui = require("chronicle.v1.ui")
local damage = require("chronicle.v1.events.damage")
local metric = ui.metric(UIParent, "damage-total", "Damage", 0, 16, -16)
local total = 0
damage.onEvent(function(event)
  -- A host-bounded record: source, target, amount and offsetMs.
  total = total + event.amount
  metric.set(total)
end)
```

## Boundaries and limitations

The server accepts only regular tar files, bounded to 8 MiB upload, 16 MiB expanded data, and 128 files. It rejects links, traversal, duplicate paths, unknown package file types, and reserved module paths; raster assets must be declared and have matching PNG/JPEG/WebP signatures. It repackages validated files as a sorted ZIP. The panel loader independently validates the ZIP before starting a dedicated Fengari worker. Lua callbacks have instruction limits, scene messages have size and geometry checks, damage projection has event and output limits, and the host terminates a worker that exceeds its time budget. Workers are not an OS memory sandbox; a malicious script can still consume CPU/memory up to browser limits.

The public API catalog lists modules with an available release, but instance selectors currently list only modules the signed-in user owns or contributes to. Guide projects can be created and drafted but **cannot yet be published** through this project system; PR #1217's built-in guide format remains separate. There is currently no general network/API capability and no byte-accurate heap quota. The workshop assistant cannot run instance previews. Sharing a channel means the author's next publish can change what viewers run; there is no stored old artifact for rollback.

## Local MCP browser tools (beta)

The local companion daemon exposes the same browser tool contracts as Chronicle's in-site assistant. Follow the [chronicle-mcp setup instructions](https://github.com/Emyrk/chronicle-mcp) for the protocol 3 daemon and authenticated MCP HTTP client connection, open a normal module edit page, and click **Connect agent** in the header. After the first successful connection, later visits call the daemon’s credential-free `GET http://127.0.0.1:17643/healthz` on load (expecting `service: "chronicle"`, `protocol: 3`) and offer to reconnect when the daemon is running. The legacy Node stdio bridge is not compatible with protocol 3. No pairing URL, local Lua files, or upload step is required.

The working copy lives entirely in the browser. The available module tools are `read_lua_files`, `edit_lua_file`, `run_startup_check`, `run_preview`, and `save_lua_files`. The save tool requires `expected_revision` from a fresh read and saves to main without a browser approval. Saving never tags a release. Direct editor Save and Tag release actions retain their existing behavior. The browser editor's existing supported-file and size limits apply; MCP does not add support for arbitrary filesystem packages.

Protocol 3 supports named browser connections and explicit agent ownership. Start with `list_connections`, then call `select_connection` with `{connection_id}` for the intended tab. There is no implicit selection, even with only one connection. `whereami` returns the selected connection's status and page identity, including URL, session ID, and page generation. URL fragments are excluded. Use `release_connection` with `{connection_id}` when finished with a tab. While connected, in-app navigation (including Back/Forward) asks for confirmation; reloads, tab close, and external navigation use the browser's unload warning. Canceling keeps the current page and its generation. Confirming navigation changes the generation, even when returning to the same URL, and invalidates pending tool calls and approvals. The connection follows the approved tab to the next page. Disconnected navigation retains its existing behavior and unsaved-edit warnings. The local MCP server emits tool-list-change notifications when the active catalog changes. Clients that cache tools may need to refresh or reconnect. Other registered browser capabilities can be exposed after navigation, but the module editor is the primary supported workflow. Backend-executed inference tools are not exported by this bridge.

The connection panel starts with a module author/slug or page-path name. Edit **Connection name** and click **Rename** to update it without reconnecting. **Copy connection ID** provides the exact ID for agent selection. Names are display labels, not identifiers. The panel shows connecting, connected, reconnecting, or error state and the current owner's name, version, and agent ID as plain text. Connection identity and controls stay in memory, not browser storage.

**Revoke agent access** cancels the current agent's work and approvals while keeping the browser connection available. The agent must select it again to resume. **Disconnect local MCP** stops the browser connection and sends a best-effort disconnect request. Either action asks for confirmation when work or a local tool approval is pending. If revocation fails, the panel shows an actionable error; disconnect if you need to stop browser access immediately. Reconnection does not waive tool approvals.

Chronicle owns the contracts: `GET /api/v1/inference/client-tools` returns schemas, descriptions, capability versions, effects, and confirmation policy directly from the same Go definitions used by inference. `POST /api/v1/inference/client-tools/validate` validates arguments before browser execution. Both endpoints require the existing authenticated `use_inference_chat` permission but do not require configured provider credentials or invoke inference. The browser intersects the catalog with currently available registered handlers and dispatches through the existing inference runtime. External calls cannot supply confirmation policy and do not bypass confirmations through YOLO.

Connected pages also advertise three read-only guidance tools: `gen_page_context`, `list_skill`, and `read_skill`. Start with `gen_page_context`: it returns the current page identity and available capabilities plus the exact static, skill-composed system prompt used by the page's UI assistant. Its instructions direct external agents to call `list_skill` and read relevant skills before acting. Skill content comes from Chronicle's existing runtime registry; the workshop additionally exposes `lua-module-api` from the same API reference embedded in its UI prompt. Guidance changes with the page and pending reads are invalidated on navigation. It does not include conversation history, credentials, user settings, or debug snapshots. Prompt references do not grant access to tools that are not advertised, and external calls still require browser approval regardless of in-site YOLO wording.

The provider-independent guidance endpoints are `GET /api/v1/inference/client-tools/context`, `GET /api/v1/inference/client-tools/skills`, and `GET /api/v1/inference/client-tools/skills/{skillID}`. The browser supplies its active `capability_id` (`lua-editor`, `instance-page`, or `search-page`); omitting it selects site help. They use the same authentication and inference permission gate as the tool catalog, and return bounded canonical content rather than silently truncating it.

The protocol-v3 bridge uses bounded HTTP polling to fixed loopback `127.0.0.1:17643`, not WebSockets or an external relay. Clicking Connect bootstraps a random bearer token from the origin-checked local `/v1/connect` endpoint. Defaults allow `https://chronicleclassic.com` and `http://localhost:4000`; pass `--origin https://your-site` when starting the daemon for another site. The initial bootstrap has no manual pairing code. Subsequent browser calls require the connection token; tool execution also requires explicit agent ownership of that connection. Older protocol-v1 and protocol-v2 processes are incompatible and must be restarted with the updated tooling.

Chronicle credentials and raw event streams remain in the browser. Tool output and page URL are sent to the local agent and may include player names, encounter data, and URL query parameters. Connect only to a trusted agent. `?safe=1` disables local execution. The browser and MCP process must share loopback connectivity. Local-network permission may be required; do not disable browser security flags. Stop any separately running dev server on port 17643 before starting MCP.
