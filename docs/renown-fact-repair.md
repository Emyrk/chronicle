# Historical Renown fact repair

New parse and ranking-run refreshes earn player and guild facts immediately. Deleting a log removes facts that no surviving duplicate backs; a later re-upload can earn that kill once again. The daily `dispatch-renown-repair` River job enqueues bounded `repair-renown-facts` passes for the root tenant and each tenant to fill historical missing facts for surviving logs. It runs alongside, but independently from, the daily rating rebuild: facts repaired after a rating snapshot are reflected in the next rebuild. An operator can also enqueue `repair-renown-facts` with `{"tenant_id":"<tenant UUID>","after_run_id":"00000000-0000-0000-0000-000000000000"}` for one tenant, or manually dispatch a pass through River's normal job insertion API (`queue.Insert(ctx, servicerankings.ArgsDispatchRenownRepair{}, nil)`). Use the nil UUID for the root tenant. No repair or backfill runs as a startup migration.

Each low-priority rankings job processes at most 200 canonical runs, inserting missing player and guild facts with conflict-safe queries. A full page enqueues the next page with a durable `after_run_id` cursor before completing. River retries the same page if an insert fails. A successful page followed by a process crash can safely be retried, and re-enqueuing the dispatcher repeats facts without awarding them twice. The cursor is a high-water mark for that pass, not a permanent checkpoint: the next daily (or manually dispatched) pass picks up historical runs added behind it. Monitor `repair-renown-facts` jobs in the rankings queue for failed jobs and retry them before considering a pass complete. Deleted source logs cannot be reconstructed by this repair.
