# Historical Renown fact repair

New parse and ranking-run refreshes earn player and guild facts immediately. Historical missing facts can be repaired with the River `dispatch-renown-repair` job, which enqueues `repair-renown-facts` for the root tenant and each tenant. An operator may instead enqueue `repair-renown-facts` with `{"tenant_id":"<tenant UUID>","after_run_id":"00000000-0000-0000-0000-000000000000"}` for one tenant. Use the nil UUID for the root tenant. Enqueue through River's normal job insertion API (for example `queue.Insert(ctx, servicerankings.ArgsDispatchRenownRepair{}, nil)`); this is deliberately **not** a startup migration or recurring full-history scan.

Each low-priority rankings job processes at most 200 canonical runs, inserting missing player and guild facts with conflict-safe queries. A full page enqueues the next page with a durable `after_run_id` cursor before completing. River retries the same page if an insert fails. A successful page followed by a process crash can safely be retried, and re-enqueuing the dispatcher repeats facts without awarding them twice. The cursor is a high-water mark for that pass, not a permanent checkpoint: another operator pass is needed for any historical runs added behind it. Monitor `repair-renown-facts` jobs in the rankings queue for failed jobs and retry them before considering a pass complete. Deleted source logs cannot be reconstructed by this repair.
